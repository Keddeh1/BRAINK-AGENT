# BRAINK_AGENT engineering monograph

## 1. Abstract

This integration makes the existing BRAINK runtime usable as a services manager while preserving native lineage. It joins durable family workflow, team execution, VFS custody, owner control and protected cloud adapters. Its engineering claim is bounded orchestration with reproducible evidence, not unconstrained autonomy or universal expertise.

## 2. Problem and scope

A registry entry, agent name or configured endpoint cannot establish a running, qualified service. The manager must preserve the transition from defined purpose to admitted identity, execution, durable outcome and separate assessment. Public GitHub delivery adds a source-provenance boundary distinct from private service access.

## 3. Source basis

The implementation derives from actual public Keddeh source identified by commit and file hash, not a generated replacement architecture. Native team workers own lease/retry rules and nested VFS; native family source owns identity, continuation, capability/task, memory and transaction behavior; ToT owns its evaluation receipt. The resident product registry keeps original system identities. Source-backed research handoffs guide future sector admission but are not fabricated as implemented expertise.

## 4. Method

Inspect mounted source and repository visibility. Select only eligible native bytes. Preserve them unchanged and implement narrowly declared adapters. Use exact capability matching to correct the legacy routing ambiguity. Implement owner/public separation at the HTTP boundary. Write state before remote dispatch, and resolve uncertainty with readback instead of retrying writes. Test crash/restart and adversarial inputs before source publication.

## 5. Architecture and execution

A family birth commits native memory and task purpose in a single native transaction. Team instantiation then binds immutable definitions to stable member identities and VFS scopes. A bounded worker claims a leased job, produces an artifact and commits its native continuation. A separately launched observer reads stored bytes and receipts. The manager's remote path retains actor output and later native command-status observations as different states.

Composed finite circuit and shell workloads demonstrate more than a text canary: the original family workflow applies finite engines, retains their result under existing matrix/memory/VFS identities, and survives restart with immutable request identity. These are software computations, not physical quantum hardware or general model inference.

## 6. Evidence and findings

Local integration and original native tests produce retrievable execution records. Independent engineering review reproduced admission and containment defects not detected by the initial tests, leading to typed-list capability checks, family-database symlink guards and preflight result/key bounds. Final counts and reopened/closed findings live in evidence records rather than being fixed prematurely in this manuscript.

## 7. Limitations and falsification

Same-UID hostile code is outside the local trusted-process boundary. Namespaces are not separate credential tenants. A process observer is not an independent model. Configured adapters are not cloud deployment proof. A native task marked resolved establishes capability routing, not scientific truth. A sector record requires applied expert qualification and analyst work before claims of useful market delivery. A broad native product registry is not evidence that every operation is admitted by this manager.

The implementation is falsified within scope if a stale lease can commit, changed request IDs overwrite prior outcomes, unauthenticated HTTP exposes owner state, private source enters the public artifact, malformed capabilities resolve by substring, or a crash produces false completion. Tests explicitly challenge those boundaries.
